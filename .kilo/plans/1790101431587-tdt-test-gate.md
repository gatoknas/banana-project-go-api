# Plan: Reliable Table-Driven-Test (TDT) enforcement for the Go API

## Goal

Make the existing TDT rule reliable in two independent layers:

1. **Agent-side (always-on):** every Go change must ship/update table-driven tests and run the gate before the task is reported done.
2. **Deterministic gate:** a hard check that fails on (a) a changed non-test Go file with no sibling `_test.go`, and (b) a changed package below an 80% coverage floor. Runs in pre-commit and in CI.

## Current state (evidence)

- The mechanism is a **skill**, not a hook or agent: `.agents/skills/go-master-api/SKILL.md` (siblings `go-openapi-docs`, `go-memory-perf`). Section 5 mandates TDT.
- Nothing invokes it deterministically: no project `kilo.json`, no `AGENTS.md`, no `.github/` workflow.
- `.agents/` is gitignored (`.gitignore:34-35`) and untracked (`git ls-files .agents` is empty), so the skills are local-only and vanish on a clean clone.
- Coverage is inconsistent. Tests exist for `service/{category,product}`, `middleware/cors`, `handlers/{hello,category}`, `email/{parser,client}`. **No tests** for `handlers/{user,sale,product,auth,health,email}`, `service/{user,sale,email}`, `repository/*`, `auth/*`, `middleware/{auth,role}`.
- GitHub remote: `github.com/gatoknas/banana-project-go-api`. `go.mod` declares `go 1.26.3`, so the Go 1.24+ `tool` directive is available.

## Decisions (agreed)

| Topic | Decision |
|---|---|
| Enforcement layers | Both: agent-side guidance **and** a hard gate |
| Rule 1 | Changed non-test `.go` under `internal/` must have a sibling `_test.go` |
| Rule 2 | 80% statement coverage floor, **changed packages only** |
| Coverage exclusions | `internal/models`, `cmd/`, `db/`, generated `*.pb.go` |
| Coverage tool | `github.com/vladopajic/go-test-coverage/v2`, pinned via `go.mod` `tool` directive, invoked as `go tool go-test-coverage` |
| Checker | Single cross-platform Go command `cmd/testgate` |
| Local hook | lefthook `pre-commit` |
| CI | GitHub Actions on PRs to `main` and pushes to `main` |
| Skills | Move `.agents/skills/*` to `.kilo/skills/*` and commit; drop the `.agents/` ignore |
| Agent-side extras | `AGENTS.md` rule + committed skills + `/tdt` command |

## Implementation tasks (ordered)

1. **Move skills.** Copy the three `.agents/skills/<name>/SKILL.md` files to `.kilo/skills/<name>/SKILL.md`, verify Kilo still lists them, then delete `.agents/` and remove its `.gitignore` entry.
2. **Pin the coverage tool.** Add the `tool` directive to `go.mod`, run `go mod tidy`, confirm `go tool go-test-coverage --help` works.
3. **Commit the base config** `.testcoverage.yml`: `profile: cover.out`; `threshold.file/package/total: 0`; `exclude.paths` = `^internal/models`, `^cmd/`, `^db/`, `\.pb\.go$`. Changed-package enforcement is injected at runtime, so the committed file must not carry a global 80.
4. **Implement `cmd/testgate`.** Flags and behavior:
   - `-staged` → changed set = `git diff --cached --name-only --diff-filter=ACMR` (pre-commit)
   - `-base <ref>` → changed set = `git diff --name-only --diff-filter=ACMR <ref>...HEAD` (CI, default `origin/main`)
   - `-all` → whole-repo audit (used on pushes to `main`)
   - Rule 1: for each changed path matching `internal/**/*.go`, not `_test.go`, not under an excluded dir → require `<dir>/<base>_test.go` on disk; collect all failures before exiting.
   - Changed packages = directories containing any changed `.go` file (test-only changes count).
   - Write a temp config = `.testcoverage.yml` + `override` entries `^<module-path>/<pkg>$` → `threshold: 80` for each changed, non-excluded package.
   - Run `go test ./... -coverprofile=cover.out -covermode=atomic -coverpkg=./...`; fail on non-zero.
   - Run `go tool go-test-coverage --config=<temp>`; fail on non-zero.
   - Print a per-rule summary and exit 1 on any failure; clear error if the base ref or the tool is missing.
   - Edge cases: ignore deletions (`ACMR`); skip `vendor`, `docs`, generated files; empty changed set is a pass.
5. **Tests for testgate.** `cmd/testgate/main_test.go` with table-driven cases for changed-file filtering, rule 1 pass/fail (including new package and renamed file), excluded dirs, override generation, and empty diff. Use a temp dir / injected `git` output so no real repo mutation is needed.
6. **lefthook.** `lefthook.yml` with a `pre-commit` command `go run ./cmd/testgate -staged`. Document `lefthook install` in `README.md`.
7. **CI workflow.** `.github/workflows/tdt-gate.yml`:
   - triggers: `pull_request` → `main`, `push` → `main`
   - `actions/checkout@v4` with `fetch-depth: 0` (needed for the base diff)
   - `actions/setup-go` with `go-version-file: go.mod` and module cache
   - PRs: `go run ./cmd/testgate -base origin/main`; pushes to `main`: `go run ./cmd/testgate -all`
8. **AGENTS.md.** State that any change to Go files under `internal/` or `cmd/` must add/update the sibling `_test.go` using the table-driven pattern (`t.Run`, `wantErr`, mocked interfaces), must run `go run ./cmd/testgate -staged` before reporting completion, and must not use `--no-verify`. Point to `.kilo/skills/go-master-api/SKILL.md`.
9. **`/tdt` command.** `.kilo/command/tdt.md`: load the `go-master-api` skill, inspect the current diff, generate/update TDT tests for changed Go files, run `go run ./cmd/testgate -staged`, and report per-file results and remaining failures.

## Validation

- `go build ./...` and `go test ./...` pass on the clean tree.
- `go run ./cmd/testgate -all` reports pass on the clean tree.
- Negative rule 1: temporarily edit `internal/handlers/health.go` with no test file → gate fails naming that file; revert.
- Negative rule 2: temporarily add an uncovered branch to a tested package → gate fails on the 80% override; revert.
- `go test ./cmd/testgate/...` covers the checker's own logic.
- Open a throwaway PR → confirm the workflow runs and fails/passes as expected; confirm `lefthook install` + a commit runs the gate locally.

## Risks and caveats

- Rule 1 cannot detect a test file that exists but was not updated for changed behavior; the 80% floor is the only partial mitigation.
- `-coverpkg=./...` and the full `go test ./...` add a few seconds to every commit.
- Developers can bypass pre-commit with `--no-verify`; CI remains the real gate.
- Adding the `tool` directive rewrites `go.mod`/`go.sum` and requires Go ≥ 1.24 (repo is on 1.26.3).
- If Kilo does not discover `.kilo/skills/` in this setup, the skills must be re-pointed via the `skills.paths` config field; verify in task 1 before deleting `.agents/`.
- Legacy untested packages stay unenforced until a file in them changes.

## Out of scope

- Backfilling tests for the 11 legacy untested packages.
- Changes to the OpenAPI or memory-perf skills beyond relocation.
- Any endpoint, handler, or business-logic change.

## Open questions

None blocking. Two defaults chosen for the plan and easy to revisit: pushes to `main` run `-all`, and the 80% floor applies per changed package rather than per file.
